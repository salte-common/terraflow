# Example Projects

This directory contains complete example projects generated using `terraflow new` for reference.

## Available Examples

### Project Examples

- **[AWS + JavaScript](./aws-javascript/)** - Complete AWS project with JavaScript application code
- **[Azure + TypeScript](./azure-typescript/)** - Complete Azure project with TypeScript application code
- **[GCP + Python](./gcp-python/)** - Complete GCP project with Python application code

### Cursor Instructions

- **[cursor-terraflow-instructions.mdc](./cursor-terraflow-instructions.mdc)** - Cursor rules file for using Terraflow in this project. **Included automatically** when you run `terraflow new` (as `.cursor/rules/terraform.mdc`). Focuses on day-to-day usage: plan, apply, workspace derivation, configuration. For existing projects, copy to `.cursor/rules/` so Cursor knows how to work with Terraflow.
- **ai-metadata.mdc** - Cursor rules file for maintaining `.ai-metadata.json`. **Included automatically** when you run `terraflow new` (as `.cursor/rules/ai-metadata.mdc`). Instructs Cursor to update `.ai-metadata.json` when creating or modifying files checked into source control.
- **[cursor-development-standards.mdc](./cursor-development-standards.mdc)** - Cursor rules file for development standards. **Included automatically** when you run `terraflow new` (as `.cursor/rules/development-standards.mdc`). Tailored to the scaffold options (language, provider, test framework); references [salte-common/standards](https://github.com/salte-common/standards); instructs Cursor to check for `SPECIFICATION.md` in the project root. (Example shown is TypeScript + AWS.)

## Using These Examples

These examples demonstrate the complete project structure generated by `terraflow new`. You can:

1. **Browse the structure** to understand what files are generated
2. **Reference the configuration** to see how `.tfwconfig.yml` is set up for each provider
3. **Copy patterns** from the Terraform files for your own projects
4. **Study the application code** to see language-specific templates

## Generating Your Own

To generate your own project:

```bash
# AWS with JavaScript
terraflow new my-project --provider aws --language javascript

# Azure with TypeScript
terraflow new my-project --provider azure --language typescript

# GCP with Python
terraflow new my-project --provider gcp --language python

# GCP with Go
terraflow new my-project --provider gcp --language go
```

See the [Project Scaffolding Guide](../scaffolding.md) for complete documentation.

## Example Structure

Each example project includes:

```
<project-name>/
├── .ai-metadata.json         # AI code tracking (initialized by terraflow new)
├── .cursor/
│   └── rules/
│       ├── terraform.mdc             # Cursor instructions for Terraflow (from terraflow new)
│       ├── ai-metadata.mdc           # Cursor instructions for .ai-metadata.json maintenance
│       └── development-standards.mdc # Cursor instructions (language, platform, salte-common/standards)
├── src/
│   ├── main/          # Application main files
│   └── test/          # Test files
├── terraform/
│   ├── modules/       # Terraform module templates
│   ├── _init.tf       # Provider and backend configuration
│   ├── inputs.tf      # Input variables
│   ├── locals.tf      # Local values (tags, etc.)
│   ├── main.tf        # Main infrastructure resources
│   └── outputs.tf     # Output values
├── .tfwconfig.yml     # Terraflow configuration
├── .env.example       # Environment variables template
├── .gitignore         # Git ignore rules
└── README.md          # Project documentation
```
